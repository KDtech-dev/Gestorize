Autenticação

Token Sanctum

Faça POST /login com e-mail e senha. A resposta inclui data.token; envie esse valor nas demais rotas protegidas:

Authorization: Bearer SEU_TOKEN
Accept: application/json
Content-Type: application/json

O token expira em três horas. Use POST /refresh antes do vencimento para substituí-lo. O logout revoga o token atual.

{
  "success": true,
  "message": null,
  "data": {"token":"...","expires_at":"...","user":{}},
  "meta": null
}

Permissões e organização

Além de autenticação, a rota pode exigir uma permissão específica. A conta deve estar vinculada a uma organização ativa para acessar dados operacionais; os registros retornados pertencem à organização do usuário.

As permissões individuais ampliam o papel do usuário. Elas não removem permissões herdadas do papel.

Respostas e erros

A maioria dos endpoints usa o envelope abaixo. Alguns endpoints administrativos retornam success e data sem message; a listagem paginada de usuários também traz metadados de paginação do Laravel.

2xx · sucesso

{
  "success": true,
  "message": "Operação realizada com sucesso.",
  "data": {},
  "meta": null
}

Erros da API

{
  "success": false,
  "message": "Descrição do erro.",
  "code": 403
}
HTTPQuando ocorreFormato / observação
201Recurso criado (por exemplo, cliente, venda, funcionário, etiqueta).Resposta de sucesso com o recurso criado em data.
401Token ausente, inválido ou expirado.Envelope de erro; autentique novamente ou atualize a sessão. Credenciais inválidas no login retornam 422.
403Sem permissão, organização inativa, ou conta global tentando acessar rota operacional.Envelope de erro com a mensagem da API.
404Recurso não encontrado ou fora do escopo da organização.Envelope de erro. O registro de outra organização não deve ser revelado.
422Campo ausente/inválido ou regra de negócio não atendida.Falhas de validação incluem errors por campo; algumas regras de negócio retornam somente success, message e code.
429Limite de tentativas excedido em rotas com throttle.Resposta de limite de requisições.
500Erro inesperado do servidor.Envelope de erro; a mensagem depende da exceção gerada.
Validação: o campo errors mapeia cada nome de campo para uma lista de mensagens. A resposta de erro inclui também success: false e o código HTTP.
{
  "success": false,
  "message": "A quantidade deve ser pelo menos 1.",
  "code": 422,
  "errors": {"itens.0.quantidade": ["A quantidade deve ser pelo menos 1."]}
}

Organizações e dados globais

Clientes, funcionários, fornecedores, produtos, orçamentos, vendas e operações de etiquetas são isolados por organização. Papéis, permissões, categorias e unidades de medida são globais e compartilhados entre organizações.

Somente o administrador global pode listar, criar e alterar organizações, consultar métricas globais e ajustar os padrões globais dos papéis. Um Gestor administra usuários e permissões individuais dentro da própria organização. O Funcionário acessa os recursos permitidos pelo seu papel e pelas permissões adicionais da sua conta.

O README principal do repositório apresenta a arquitetura e as regras de acesso. O guia do backend descreve a instalação e a execução local da API.
